# Synapse 长期迁移任务提示词

本文件保存本轮长期任务的可复用提示词。具体范围以 [集成计划](integration-plan.md) 为准；身份、租户与 Workspace 隔离以 [租户契约](tenancy-contract.md) 为唯一权威；完成状态以 [开发台账](development-status.md) 和独立验收材料为准。

## 可用于接续任务的提示词

继续 Synapse 的长期迁移任务。以 shadcn-admin 为前端基础、Synapt 为业务后端来源，将 AgentScope Demo 融入同一套前端和同一个 FastAPI 服务。保留租户与 Workspace 管理、人脸识别；排除原 Synapt 其他平台管理业务和加密管理业务。按 `docs/integration-plan.md` 逐项推进，已完成的功能也要依据本轮租户优化原则复核，而不是只开发剩余模块。

每个功能点按以下流程处理：

1. 先指派独立 UX 子智能体，审视信息架构、主要操作、筛选与选择、空白/加载/错误/部分成功、权限提示、移动端、键盘与读屏、中英文。提交可审阅的 UX 方案，区分跨模块标准与该业务的专属规则。
2. 对照现有代码梳理前端交互、API 契约、服务层、数据模型、权限与作用域、错误处理。先确定数据归属是全局账号、租户、Workspace 还是个人；不得把平台管理员身份推断为租户/空间业务成员资格。
3. 由单独的实现子智能体处理一个有边界的功能点，明确文件所有权，避免并行覆盖。前端体验、接口与服务、数据归属与权限、失败/并发行为和验收条件同时设计。优先复用通用组件与模式，允许业务差异；不得机械复制租户管理的字段或动作。
4. 若需改变路由、请求/响应字段、数据归属、唯一约束或隔离规则，先写旧调用方、兼容期、回填、回滚方式，再实施。身份和隔离规则只维护在 `docs/tenancy-contract.md`，其他文档引用它，不重复写另一套权威定义。
5. 由不同于实现者的子智能体独立审查和验收。静态检查、代码已写、构建通过、真实 API/浏览器功能已验收分别记录，不能互相替代。模拟模型、渠道或 SDK 结果须明确标为模拟。
6. 每项结果更新 `docs/development-status.md`：写清已完成、待修复、待产品决策、待独立验收和证据路径。继续按优先级修复当前功能，再迁移下一个功能点。

当前首先参考 [租户优化原则与差距清单](tenant-optimization-principles-and-gap-review.md)，从已迁移的全局用户、角色、菜单等模块逐项复核，并继续处理 AgentScope 与系统任务的未验收项。不要仅凭页面外观推断规则。遇到代码无法确定的产品决策，提出具体选项；在等待答复时继续不依赖该决策的工作。

## 本轮已确认的产品选择

- 租户列表多选用于批量停用/启用，首期复用单租户 PATCH 并逐项反馈。
- shadcn-admin 示例页从正式导航移除；源码参考是否清理另列范围任务。
- 中英文国际化先覆盖正式产品页面。

## 尚待产品回答

- 全局用户管理是否同时保护当前登录的管理员和最后一位平台管理员，避免自停用/自删除或平台管理入口被锁死。
- 软删除后的用户名与邮箱是否永久保留唯一性，还是允许新账号复用；后者需要数据库迁移设计。
- 全局用户列表首期新增状态与平台角色筛选、仅状态筛选，或暂不新增筛选。

以上待决事项不能视作默认批准。当前代码和历史验收的实际状态应重新读取工作树、Git 提交和 `docs/development-status.md`，不得用这份提示词替代代码证据。
