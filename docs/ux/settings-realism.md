# 个人设置域“真实可用性”UX 审查与实施契约

状态：独立 UX 审查与可实施契约；仅设计，不是实现记录或独立验收。本文按当前设置实现和后端路由决定每项在真实接入前如何呈现，并为后续单一设置功能实现定义数据归属、状态、接口及验收边界。实施和验收必须分别委派；不得以构建通过或模板演示行为宣称真实持久化完成。

## 审查依据与当前事实

- 身份及数据归属以[租户契约](../tenancy-contract.md)为唯一权威：登录账号是全局身份；租户成员和 Workspace 成员关系彼此独立。本文涉及的个人资料、凭据和个人设置均归属当前全局账号，不属于 Tenant 或 Workspace，不得因切换租户/Workspace 改变或泄漏。
- 复用[跨模块标准第 2、3、7 节](../tenant-optimization-principles-and-gap-review.md)：先定义归属、API/服务、前端状态、失败和验收；读写服务端仍须按可信的当前账号校验；前端缓存/浏览器偏好不是授权依据；逐项独立验收。
- [开发台账设置域记录](../development-status.md)（2026-10-13）只确认资料、账号、外观、显示和通知已改为“当前设置摘要 + 编辑弹窗”，桌面/移动布局与导航改动已有静态检查和既有前端测试；明确 Display/Notifications 仍为模板演示提交、未接持久化 API，未宣称真实设置保存验收。
- **当前代码事实：** `profile-form.tsx` 调用 `PATCH /account/profile`，返回 `AuthUser` 后更新 auth store；API 在全局当前用户上写入 `User` 并提交数据库。`account-form.tsx` 调用 `POST /account/password`；后端校验当前密码、更新哈希、提升 `token_version` 并撤销旧会话，前端清空登录态后转登录。当前实现使 email 字段可编辑，但没有发现验证/确认邮箱流程契约；头像 URL 也没有发现格式/来源验证或上传契约。
- **当前代码事实：** 外观页面编辑主题和字体，调用本地 provider 写入浏览器 Cookie（主题 `vite-ui-theme`、字体 `font`），不是账号 API；交互真正会更新当前浏览器外观，但没有跨浏览器、设备或账号同步语义。`AppearanceForm` 仅支持 `light`/`dark` 的表单校验，而 provider 同时支持 `system`，两者可选项并未完全对齐。
- **当前代码事实：** 显示表单默认 `recents`、`home`，通知表单使用硬编码默认值；二者提交 `showSubmittedData` 后关闭弹窗，没有服务端保存、读取或当前值摘要，不能称为已保存。通知中的安全邮件项虽禁用但没有明确说明原因；“移动设备设置页”链接指向 `/settings`，而该路由是个人资料页，不是独立移动端设置页面。
- 可见测试包括 `apps/web/src/components/config-drawer.test.tsx` 的本地主题 Cookie 行为等，但未发现覆盖 Profile/Account/Appearance/Display/Notifications 页面提交、持久化读回和失败恢复的设置域专属测试。台账提到既有 5 个前端测试文件 47 项通过，不等于上述行为已获验收。

| --- | --- | --- | --- |
| 资料字段 | 全局用户 `User`，由会话解析出的当前用户；不是 Tenant/Workspace 属性 | 已有 `GET /auth/me`；`PATCH /account/profile`，仅允许白名单字段，返回规范化 `AuthUser`。后续应确认邮箱唯一性与验证流程、头像 URL 校验/上传策略，再决定可编辑字段。 | 服务端数据库；所有登录设备重新读取后取得更新值。成功以服务器 2xx 响应且返回规范化当前用户为准。 |

| 通知偏好 | **拟议**当前全局用户的持久化偏好；不以 Tenant/Workspace 为键，实际组织级投递策略另有授权定义 | 需定义通知类别与渠道的产品语义、必需/可退订规则、投递服务消费方式；再通过 `GET/PATCH /account/preferences` 的 `notifications` 部分或专属端点返回规范化设置。服务校验当前账号和可配置字段，不接受客户端决定账号身份。 | 服务端数据库仅说明意愿偏好；并不保证发送/送达。成功只表示偏好被服务器接受并持久化，不承诺实际通知送达。后端未实现前不可编辑。 |

## 页面、表单与动作状态

### 页面读取与只读摘要

1. 设置域加载期间显示明确骨架/“正在加载账号设置”，不将表单代码中的初始化默认值渲染成用户当前设置。
2. Profile 从已加载的 auth 用户信息填充摘要；所有字段以明确的空值状态呈现。API/会话恢复未完成时摘要保持加载态；读取失败则隐藏可能过期的敏感资料，显示可重试错误，不将缓存数据标成最新。
3. Account 的摘要只说明“可修改密码”，不得展示任何凭据、密码长度以外的未确认规则或虚构安全通知状态。
4. Appearance 摘要显示 provider 当前实际值、最终生效主题（system 时显示系统模式及当前解析明暗）和“仅此浏览器”。本地 Cookie 不存在时显示 provider 默认值及“默认”标识，不称为服务器加载结果。
5. Display/Notifications 在上线 API 之前使用显眼且持久的“暂不可用”标识，并解释该页尚未接入实际保存/生效；不给可提交控件，不显示静态默认值作为当前值。

### 编辑、提交、取消与错误

- **进入编辑：** 每次打开弹窗均用最新服务端结果或本地 provider 值建立初值。弹窗内编辑不影响只读摘要；Appearance 因即时预览会改变本机显示，需提供恢复/取消语义。重复打开不得沿用上次取消的未提交草稿。
- **编辑态：** 所有输入使用可见标签、当前值、明确可选范围和服务端验证提示。输入尚未提交时明确标记“未保存更改”。邮件、资料等个人字段旁提供范围/隐私说明（见下）。
- **提交中：** 防止重复提交；主按钮显示“正在保存/正在更新密码”，并禁用冲突动作。不要在请求发出时乐观更新只读摘要或给成功通知。
- **成功：** Profile 只在 2xx 返回规范化 `AuthUser` 后更新 auth store、刷新依赖账号显示的数据、关闭弹窗并显示已保存成功。Password 只在后端 204 后清除受影响会话并跳转重新登录，显示重新登录说明。Appearance 只在 Cookie 可写且偏好应用后关闭/更新摘要，成功文案限定在此浏览器。未来 Display/Notifications 只在后端明确返回已持久化值后更新摘要。
- **失败：** 保留用户输入，弹窗保持打开；不改变摘要、不丢弃草稿。字段错误按 API field errors 关联对应控件；`401` 转登录并说明会话失效，`403` 表示账号无权修改且不提供越权重试；`409`/业务冲突解释冲突并允许用户修正；网络、超时和 `5xx` 显示可恢复的重试入口。不要把服务器原始错误 detail 当唯一用户文案。
- **结果不确定：** 请求超时/断网可能发生在服务器已提交而响应未抵达之后。不得宣告失败或成功；显示“未能确认是否保存，请重新加载核对”，先重新 GET 当前服务端值后再允许再次提交，避免重复执行密码变更或覆盖远端更新。
- **并发编辑：** API 若提供 `updated_at`/ETag/version，写入使用条件更新；冲突后重新加载服务端版本，由用户比较或重新编辑，禁止静默覆盖。未提供并发版本字段时，前端至少提交前刷新并以服务器返回值为最终状态；验收报告注明缺少乐观并发控制。
- **取消/关闭：** 未提交草稿关闭前，在有未保存改动时询问“放弃更改？”；取消关闭继续留在编辑态，确认关闭丢弃草稿。键盘 Escape 及点击遮罩遵循同一规则。Password 表单在关闭时清空密码字段；成功错误反馈不得带敏感输入。
- **部分成功：** 当前个人设置操作各自独立，因此单项成功按上述规则完成；未来批量写入若非原子，只展示逐项成功/失败、成功时间和仅对失败项重试，成功项不重复提交。不能只显示“部分失败”而隐藏哪些项保存成功。

### API 适配和隐私

- 前端集中使用现有 `api` 客户端；保持 `credentials: include` 的 HttpOnly 会话语义。个人资料与偏好请求 body 不包含 `user_id`、tenant id、Workspace id 来声明写入对象；服务端从认证会话解析当前全局用户并授权。仅用户可见数据归属全局账号；浏览器 Cookie/本地状态只能控制显示，不授予资源访问。
- `GET /auth/me` 可作为当前个人资料的来源，但若其缓存值被 auth store 复用，编辑提交必须以后端返回对象为准；登出/会话失效清理个人资料摘要和私有缓存。账号设置不能随工作区切换引起错误重取后串用。
- 资料输入可能包含个人信息，应避免在 URL、遥测、console、错误日志和 toast 中记录邮箱、电话、头像 URL 等值。密码不能进入持久化浏览器存储、分析事件、日志或错误详情。显示/通知偏好也按个人账号数据最小化处理。
- 邮箱是否可变、是否需要二次验证、唯一性冲突的稳定 `code`、头像 URL 允许协议/域名、通知同意/退订及保留期，在接口实现前作为明确待产品/安全确认项；不得由 UI 自行假设或承诺。

## 移动端与可访问性

- 320、360、390 CSS px 下检查设置导航选择器、摘要卡、全宽主按钮、弹窗/底部滚动、长标签及错误文案；不得横向溢出。主操作在窄屏下独占可触区域，复选框/开关标签均可触发；不能仅凭颜色/图标表示“暂不可用”。
- 设置路由导航在移动端跟随 TanStack Router 当前 pathname；下拉选项当前值和页面标题一致。选择分区后将焦点置于新页面标题/主区域，并让读屏用户得知已进入的分区。
- 对话框具备可访问标题/说明，打开后焦点进入对话框、关闭后返回打开按钮；Tab 焦点限制在对话框中，Escape 关闭遵循未保存确认。输入有程序化 label、描述和错误关联；密码错误不依赖 toast 单独传达。
- 使用原生/ARIA 正确的单选组、checkbox、switch 及必需状态；单选组标签、每个开关名称唯一明确，不能仅把关联说明当 label。提交按钮禁用时仍有可感知原因；`aria-busy`/`role=status` 告知提交进度，字段/全局错误用 `role=alert` 仅播报一次。
- 纯键盘可完成导航、编辑、提交、取消和错误恢复。缩放 200% 及高对比度下文本、边框、焦点指示清晰；操作目标至少 44×44 CSS px 或采用平台适配等效触控区域。屏幕阅读器验证加载/错误、只读/暂不可用范围、浏览器本地与账号持久化区别、未保存确认和成功反馈。
- 外观主题预览可能影响对比度；选择主题时保持可见焦点和弹窗可读。尊重系统减少动态效果；不得用实时视觉预览代替可访问的选中状态播报。

## 独立验收条件

验收只覆盖个人设置域，被测服务使用隔离测试账号和数据；记录浏览器、视口、语言、API 状态及数据库读回证据。模拟服务或仅 UI mock 的测试必须标为模拟，不能充当真实持久化证据。每一项由实现以外的独立验证者验收。

1. **资料真实读写：** 登录账号 A，读取 `/auth/me`；修改允许字段，`PATCH /account/profile` 后检查服务端数据库提交、响应 `AuthUser` 与重读一致；刷新/重新登录后仍一致。字段错误、空值、服务端拒绝、401、超时及并发更新不造成虚假摘要或草稿丢失。B 账号不能看到 A 的资料；租户/Workspace 切换不改变本资料归属。邮箱验证及头像上传仍需标为未覆盖/待确认，除非另行真实实现验收。
2. **密码真实变更：** 错误当前密码收到稳定错误且不撤销有效会话；有效变更收到 204、数据库仅包含新哈希、旧会话失效且需重新登录；旧密码不能再认证、新密码能够认证。浏览器历史/localStorage/sessionStorage、网络日志及 toast 不含密码。重复请求、超时后的不确定结果按重新认证与状态核验流程处理，不误报成功。
3. **外观本地语义：** 主题/字体变化确实应用并写当前浏览器 Cookie，刷新同浏览器后仍生效；另一个干净浏览器/用户未被改变。文案明确仅本浏览器。测试 system/light/dark 和所有允许字体，确认表单选项等同 provider，Cookie 被禁用/写入失败时不显示“已应用”。服务端没有对应账号更新请求。
4. **显示诚实性：** 在持久化 API 与侧栏消费未实现时，页面仅有可读暂不可用说明，无可提交假编辑器、默认值冒充当前值、成功 toast 或伪造 API 请求；窄屏和键盘仍能发现状态。若实施真实偏好 API，须再证明账号 A 的 PATCH 仅改 A、事务/失败语义明确、GET 回读和刷新后的实际侧栏呈现一致。
5. **通知诚实性：** 未接 API/投递前页面禁用编辑并明确暂不可用，无虚假当前值、错链、演示提交、保存 toast。真实接入后须分别证明服务端 GET/PATCH 归属当前全局账号、重读一致、不可变安全类别由服务器定义，以及设置效果对真实投递渠道生效；单纯 API 保存不能作为送达验收。
6. **状态/故障矩阵：** 每个可编辑区覆盖只读→编辑→未保存→提交中→成功、字段校验、403、409、401、断网、超时不确定、5xx、重新加载和部分失败；失败时不关闭弹窗、不清草稿、不更新为未确认值；部分成功可逐项区分和安全重试。
7. **双语/响应式/可访问性：** 中英文桌面及 320/360/390px 窄屏，纯键盘与至少一种屏幕阅读器验证导航、弹窗焦点进出、控件关联、错误/提交播报、触控区域、放弃确认与状态理解；附可复现截图/测试步骤及缺失的真实依赖说明。
