# F11/F11a 全局用户管理复核

状态：UX 与契约子智能体完成只读审查；这份差距清单不改变历史验收结论，也不等于当前改动已验收。依据正式 `/users` 页面与 `apps/api/app/{api,services}/users.py`；旧 Clerk/Faker 用户页面是模板演示，不是正式用户管理。

## 已符合的边界

- 全局用户属于账号层，不随当前租户或 Workspace 切换。所有用户管理端点要求 `platform_admin`；该资格不自动获得租户业务访问。
- 正式列表已把搜索和分页放入 URL；服务端用同一查询计算 `items` 与 `total`，按用户 ID 稳定排序。创建仅普通账号；状态、密码与软删除会撤销旧令牌；租户/Workspace 成员关系不随账号删除而自动改写。

## 差距与优先级

| 优先级 | 具体差距 | 拟修改文件 | 契约影响 |
| --- | --- | --- | --- |
| P1 | 搜索把 `%`、`_` 直接交给 `ILIKE`，导致输入被当作通配符；应按普通字符转义。 | `apps/api/app/services/users.py` | 保持现有参数/响应，修正匹配语义 |
| P1 | 正式表单对 409/422 只给通用错误；创建、编辑应把可确认的字段错误放在相应输入旁。停用与删除缺少统一的应用内确认及操作进度。 | `apps/web/src/features/users/index.tsx`，必要时 `apps/api/app/schemas/users.py` | 优先复用现有稳定 Problem 码；新增字段码须兼容旧客户端 |
| P1 | 软删除后的用户名/邮箱仍受全局唯一索引约束，但服务预检排除已删除记录；管理员可停用或删除自己及最后一位平台管理员。 | `apps/api/app/services/users.py`；如允许身份重用则模型与 Alembic | 产品决策后实施；身份重用需要数据契约迁移 |
| P1 | 列表只有全字段搜索；是否加状态和平台角色筛选由用户管理场景决定。若新增，URL、API、计数使用同一条件。 | `apps/web/src/features/users/index.tsx`、`apps/web/src/api/users.ts`、`apps/api/app/{api,services}/users.py` | 新参数增量兼容 |
| P2 | 窄屏表格操作拥挤；技术 ID 缺少明确用途，日期跟随浏览器默认语言；正式页面中英文与读屏/焦点仍待浏览器验收。 | `apps/web/src/features/users/index.tsx`、`apps/web/src/lib/i18n.ts` | 体验层，保持数据归属 |

不因为租户表有多选而给用户表自动加批量操作；先明确真实批量动作及服务端逐项/原子语义。角色、部门关联也不能把全局账号、租户成员和 Workspace 成员三种身份合并。

## 待决定与验收

产品待选：是否保护当前/最后平台管理员；软删身份能否复用；首期筛选字段。决定后先写迁移方式，再做可能改变数据库约束的实现。

独立验收须覆盖 `%`/`_` 搜索、筛选与跨页 `total`、403 与字段错误、状态/删除确认、当前与最后管理员规则、中英文和窄屏；生产 PostgreSQL 下的并发写入与令牌版本也应单列验证，不能由 SQLite 历史报告代替。
