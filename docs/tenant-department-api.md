# 租户部门管理 API

Status: F14a implementation contract. This API migrates Synapt department management into a tenant-owned department tree. It covers hierarchy CRUD, ordering, active/disabled status, and legacy department fields. It does not associate global accounts or tenant members with departments, and it does not depend on excluded Synapt business modules.

## 授权与作用域

Endpoints are under `/api/v1/tenants/{tenant_id}/departments`. Each request derives tenant context from the authenticated user's active tenant membership. Only built-in tenant owners and admins may manage departments; custom permissions and platform-admin status alone do not grant management. Queries use `tenant_scope`; foreign-tenant and missing IDs both return 404 `RESOURCE_NOT_FOUND`.

## 数据契约

Department and tenant IDs are decimal strings. `parent_id` is a decimal string or `null` for a root (the legacy Synapt root value `0` maps to `null`). `ancestors` is generated by the server in legacy-compatible comma-separated form: root `0`, child of root `0,{root_id}`, deeper node `0,{root_id},...`. Clients cannot set `ancestors` directly. `status` preserves Synapt values: `0` enabled, `1` disabled. Deletion is soft and excluded from normal reads.

The department fields retained are `dept_name` (30 chars), `order_num`, `leader` (20), `phone` (11), `email` (50), `status`, and generated `ancestors`, with creator/updater IDs and timestamps. Department names must be unique among non-deleted rows within a tenant. No global `SysUser.dept_id` relationship is migrated or inferred.

A parent must be an active, non-deleted department in the same tenant. Self-parenting and ancestor cycles return 409 `DEPARTMENT_CYCLE`. Reparenting refreshes `ancestors` for all active descendants in the same transaction. A department with active children cannot be soft-deleted (`DEPARTMENT_HAS_CHILDREN`). Disabled departments remain visible when the tree is read with `include_disabled=true`, the default.

## 端点

| 方法/路径 | 契约 |
| --- | --- |
| `GET /api/v1/tenants/{tenant_id}/departments?search=&status=` | Tenant-scoped flat list ordered by parent, order, and ID; optional department-name search and status filter (`0`/`1`). Returns `{items,total}`. |
| `GET /api/v1/tenants/{tenant_id}/departments/tree?include_disabled=true` | Nested tree `{items:[...]}`. When false, disabled departments are omitted. |
| `GET /api/v1/tenants/{tenant_id}/departments/{department_id}` | Read one active, non-deleted department in this tenant. |
| `POST /api/v1/tenants/{tenant_id}/departments` | Create with `dept_name` and optional `parent_id`, `order_num`, `leader`, `phone`, `email`, `status`. Root defaults to `parent_id:null`. Returns 201 and the department record. |
| `PATCH /api/v1/tenants/{tenant_id}/departments/{department_id}` | Partial update of name, parent, order, leader, phone, email, or status. Empty patches and null for non-null fields are rejected. |
| `POST /api/v1/tenants/{tenant_id}/departments/reorder` | Atomically update one or more parent/order values. Body: `{ "items": [{"department_id":"12","parent_id":"3","order_num":1}] }`; parent may be null. Duplicate, missing/cross-tenant IDs, inactive/deleted parents, and cycles are rejected. |
| `DELETE /api/v1/tenants/{tenant_id}/departments/{department_id}` | Soft-delete a leaf and return 204. |

## 错误

Errors use the app's `application/problem+json` envelope. Common codes include 401 `AUTHENTICATION_REQUIRED`, 403 `FORBIDDEN`/`MEMBERSHIP_INACTIVE`, 404 `RESOURCE_NOT_FOUND`, 409 `DEPARTMENT_NAME_CONFLICT`, `DEPARTMENT_PARENT_INACTIVE`, `DEPARTMENT_CYCLE`, `DEPARTMENT_HAS_CHILDREN`, or `DEPARTMENT_CONFLICT`, and 422 `VALIDATION_ERROR`.

## 存储 and migration

Alembic revision `0008_tenant_departments` creates `tenant_departments`, a tenant-owned table with composite parent/tenant foreign key, soft-delete flag, legacy department fields, and indexes. SQLite foreign-key enforcement is enabled by the FastAPI engine connection hook documented in `sqlite-foreign-key-enforcement.md`. The migration creates no account or membership association and imports no global department records.
